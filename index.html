A good first project is small.

02

Give the idea a shape.

These Markdown files make the project understandable before anyone starts building.

↻Suggested review loop: ask AI to create a first draft from your answers, read every line, and have a human review accuracy, missing details, and risks. Revise and approve the documents before using them to guide implementation.
✳CONCEPT-IDEA.mdThe “why” and the opportunity⌄

Start here when the project is still an idea. Keep it readable for someone who does not write code.

# Concept idea: [working title]

## The opportunity
What situation or problem made us think of this?

## Who it is for
Who experiences this? What do we know, and what are we assuming?

## The idea
In a few sentences, what might we make or change?

## Why it could help
What would be better for the intended audience?

## First version
What is the smallest useful thing we can try?

## Open questions and risks
What should we investigate or ask a person before we proceed?

03

A toolkit that grows with you.

Start with the basics. Add AI and extensions when they solve a real problem.

⌘
Your workspace

Visual Studio Code

A free code editor. Open your project folder, edit Markdown and website files, use the built-in terminal only when a guide asks you to, and keep changes visible. Install from the official site; start with no extensions or add only trusted ones.

Save & share

GitHub + GitHub Pages

GitHub stores your project and its history online. Pages can publish a static site from a repository—handy for dashboards and portfolios. A repository can be public or private; a published site should contain only information you intend to share.

GitHub Copilot for students

Eligible students may be able to access Copilot through GitHub Education. Check current eligibility, included features, model access, and terms on GitHub—these can change. Ask it to explain unfamiliar code, draft tests, or suggest a small change; review and test everything.

Optional AI tools

Claude Code or OpenAI tools

Claude Code and OpenAI coding tools (such as Codex, where available) can help work with a project. Check current account access, pricing, data settings, supported regions, and setup before choosing. You do not need multiple paid subscriptions to start.

Try asking

“Explain before you edit”

“I’m new to this. Explain what this file does in everyday language. Before changing anything, tell me your plan and which requirements it supports.”

Stay in control

“Show me how to check it”

Ask for one small change, a plain-language explanation, and a way to verify it. Do not paste passwords, API keys, private student data, or information you do not have permission to share.

04

MCP helpers: optional connections.

Connect an AI assistant to approved tools only when you know what it will access.

MCP (Model Context Protocol) is a way for compatible AI apps to connect to tools and services. It is not a checklist of files every student must install. In VS Code, a project can define servers in .vscode/mcp.json; the assistant and installed VS Code version must support MCP. Start with none, then add one trusted server at a time.

GitHub · when needed

Work with repositories

Can help an AI find repository information or work with issues and pull requests. Permissions depend on the server and your signed-in account. Prefer read-only access to start; review requested permissions and approve changes yourself.

Tavily · when researching

Search the web

A web-search MCP server can find current sources. Useful for researching a topic or checking official documentation. Verify important claims at the source; search results can be wrong and queries may leave your computer.

Filesystem · scoped access

Read project files

If your AI app needs a filesystem server, restrict its folder access to the project. Never grant an assistant your whole home folder just to edit one website.

Browser testing · later

Playwright or browser tools

Can let an assistant interact with a local site for testing. Add only if you need it, use a non-sensitive test project, and keep actions visible. It is not needed to publish a simple static page.

VS Code typically reads workspace MCP server settings from .vscode/mcp.json. These remote HTTP examples avoid putting an API key in the file; the provider may ask you to authorize access. Before connecting anything: verify the publisher and exact server source; check what data it can read or change; understand its permissions; never put API keys in a committed file; and remove a server you no longer use. An MCP server can act with the access you grant it. Ask a teacher or administrator before installing tools on a managed device.
05

Publish a static site with Pages.

A browser-only dashboard usually needs no server, build system, or package install.

1

Create your project folder

In VS Code, open a new folder. Add an index.html file. Keep the reviewed .md planning documents alongside it if you want the project story and plans in the repository.

2

Preview and ask someone to check it

Open the HTML in a browser or use VS Code’s preview options. Check on a phone-sized screen, use the keyboard, proofread, and ask a classmate or teacher to review it.

3

Create a GitHub repository

Sign in at GitHub, create a new repository, and upload your files using GitHub’s browser interface or VS Code’s Source Control view. Choose visibility deliberately. Avoid uploading private data or secrets.

4

Turn on GitHub Pages

In the repository, open Settings → Pages. Under build and deployment, choose Deploy from a branch, select your publishing branch (often main) and folder (often /(root)), then save. Follow the repository’s current Pages guide if the labels differ.

5

Visit the published link

Wait for deployment, open the URL shown in the Pages settings, and test it. A repository website URL usually includes the repository name. Share only the published information you are comfortable making public.

6

Make a change and learn the loop

Edit the file, upload or commit the change, and revisit the Pages URL. Ask users what is confusing; write the next small, testable improvement in your PLAN.md or BACKLOG.md.

!Pages is for static sites. If your project needs private user accounts, a database, secret API keys, or a server, pause and get help choosing a secure hosting design. Do not put credentials in browser-side code.
